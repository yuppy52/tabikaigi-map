# 設計書のレビュー

1. 対象を決める。引数があればそのファイル、なければ docs/ 以下の要件・設計・ADR（roadmap と learnings は除く）
2. `doc-reviewer` サブエージェントに、対象ファイルの一覧を渡してレビューを依頼する
3. 返ってきた指摘を、重さの順の表でユーザーに見せる。自分でファイルは直さない
4. ユーザーと一緒に、指摘ごとに「直す／直さない（理由）／あとで」を決める
5. 直したら、該当ドキュメントの状態を更新する
6. 最後に「今回のレビューで、次回にも効く学びがあれば `/compound` で残しましょうか」と提案する
