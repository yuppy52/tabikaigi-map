# ADR 0014：問い合わせのフォームをやめ、連絡先はこのアプリ用のメールアドレス1つにする

状態：決定（2026-11-23）

- 関係する要件：NFR-007（預かる情報から問い合わせを外す）、NFR-008（運営者と問い合わせ先）、NFR-018（削除の依頼の頼み方）
- 2026-10-04 にユーザーと決めた「問い合わせはアプリの中のフォーム（API＋D1＋Turnstile）」（NFR-018、roadmap の「問い合わせのフォーム」）を置き換える

## 背景

7-3（プライバシーポリシー）をマージした 2026-11-23 に、ユーザーから「問い合わせはアプリの中のフォームをやめて Google フォームにしたい」と提案があり、続けて「問い合わせのフォーム自体をやめよう。個人を特定できる情報は保持しない。公開に集中したい」と提案があった。

- 問い合わせのフォームはまだ作っていない（表、API、画面とも）。`/contact` は仮の画面（`NotYet.tsx`）を返すだけ
- ふだんの削除は、利用者がアプリの中で自分でできる（退出 REQ-049、グループの削除 REQ-047）。問い合わせが要るのは、招待URLをなくして自分で消せない人など、まれな場面の見込み
- 個人情報保護法の個人情報取扱事業者に当たる前提で書く（2026-10-12：[privacy](../design/privacy.md)）。その場合、苦情の申出先、開示などの請求の手続、運営者の氏名・住所（「求めに応じて回答する」形）を、本人が知れる状態にする必要がある。連絡先が何もないと、この3つの頼み先がない
- 利用者が本名を入れても、保存して扱うのは運営者なので、入れた人の責任にはならない（ユーザーの質問への答え）

## 選択肢

| | A：連絡先なし | B：このアプリ用のメールアドレスを1つ書く（推奨・決定） | C：Google フォーム | D：アプリの中のフォーム（いままでの予定） |
|---|---|---|---|---|
| 法律の3つ（苦情、請求の手続、氏名・住所の回答） | 満たせない | 満たせる | 満たせる | 満たせる |
| 作るもの | リンクを消す | リンクを替え、ポリシーにアドレスを書く | B に加えて、フォームの設定と `_redirects` の1行 | 表・API・ボット対策・画面・テスト |
| 運営者の作業 | なし | Google アカウントを1つ作る | アカウントを作り、フォームの質問と設定を決める | なし |
| 預かる情報 | なし | メールを送ってきた人の分（Gmail に残る） | 回答（Google に残る） | 問い合わせ（D1 に残る） |
| Google が送り先に増えるか | 増えない | メールを送ってきた人の分だけ増える | 増える | 増えない |
| 迷惑な送信 | 来ない | 迷惑メールが来ることはある（Gmail のふるい分け） | 止める仕組みがほぼない（2026-11-23 に `researcher` で調べた） | Turnstile で止める |

運営者の個人の Gmail を載せる案も出たが、返事で本名とプロフィール写真が見えることがある、個人の受信箱に迷惑メールが混ざる、NFR-018 の「個人のアドレスは公開しない」と逆になるので、採らなかった（2026-11-23 にユーザーが選んだ）。

## 決定（2026-11-23 にユーザーが選んだ）

1. **問い合わせのフォームは作らない**（アプリの中にも、Google フォームにも）。問い合わせの表・API・画面・Turnstile の利用先から外す
2. **連絡先は、このアプリ用に作った Gmail のアドレス `tabikaigimap.contact@gmail.com` だけ**にし、プライバシーポリシーに書く。アカウントの名前は「旅会議マップ」にし、本名と写真は出さない（作る前・作った直後に確かめる設定は、ユーザーに案内した）
3. **「お問い合わせ」のリンクは残し、行き先をプライバシーポリシーの連絡先（`/privacy#contact`）にする**（メインが決めた仮の形。どの画面にも「プライバシーポリシー・お問い合わせ」を置く決まり（NFR-008、screens）を変えずにすむため）。`/contact` の URL はなくす（`_redirects`・`_headers` から消し、404 になる）
4. 削除の依頼は、メールで招待URLとメンバーの名前を書いてもらえれば消す。1か月以内に応じる（NFR-018 の本人の確かめ方と期限はそのまま）。メールは、対応が済んでから3か月で手で消す

## 結果と注意

- アプリのデータベースには、問い合わせの情報を持たない。アプリが預かるメールアドレスはなくなる（NFR-007）
- 届いたメールは Google（米国。保存の国は選べない）に残る。プライバシーポリシーの「5. 使っている外部のサービス」「9. 外国にあるサービスの利用」に Google を足す
- ページに書いたアドレスには、迷惑メールが来ることがある。届いたメールの確認は、週1回の無料枠の確認（NFR-011）と一緒に行う
- 名前を入れる所の一言は強めず、いまの「本名でなくてもかまいません」のままにする（2026-11-23 にユーザーが決めた）
- 直すもの：requirements（NFR-007・NFR-008・NFR-018）、design（privacy、screens、data-model、api、architecture、traceability）、glossary、roadmap。コードの側は `/contact` のリンクと仮の画面、`_redirects`・`_headers`、プライバシーポリシーと使い方の文（別のプルリクエスト。配信の設定に触れるので `access-reviewer` に頼む）
