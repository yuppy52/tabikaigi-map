# ADR 0016：CodeQL は入れない（ADR 0015 の CodeQL の部分を覆す）

状態：決定（2026-11-24）

- 関係する要件：NFR-006（アクセス制御は保存先の側で守る）
- [ADR 0015](0015-pre-launch-security-tools.md) の決定 1（CodeQL を default setup で有効にする）を覆す。Strix の部分（決定 2〜5）はそのまま

## 背景

ADR 0015 をマージした後、CodeQL を有効にする手順（S-2）を出したところで、ユーザーから「なぜ必要か」「費用はかからないか」と聞かれた。説明した内容は次のとおり。

- CodeQL が拾うのは、書き方で分かる欠陥（人が入れた文字がそのまま画面や SQL に入る、時間のかかる正規表現、秘密の直書き、GitHub Actions の危ない書き方）。一番怖い認可の抜け（他人のグループを読み書きできる）は拾えない
- このアプリは、SQL を値の差し込みで書き（`.claude/rules/sql.md`）、画面では人の入れた文字を JSX で出して `innerHTML` を使わない（`.claude/rules/web.md`）。CodeQL が拾う典型的な欠陥は、もともと起きにくい
- 公開リポジトリのあいだは費用がかからない（非公開にすると有料の契約が要る）

## 選択肢

| | 入れる（推奨だった） | 入れない（決定） |
|---|---|---|
| 守れるもの | 書き方で分かる欠陥を、プルリクエストのたびに機械で拾う。公開の後に AI が書き足すコードにも効く | `/code-review`（push の前に毎回）と `access-reviewer`、API のテスト、Strix で守る |
| 手間 | 設定画面で1回有効にする。誤った指摘の確かめ | なし |
| 費用 | 公開リポジトリのあいだは 0 | 0 |

推奨は「入れる」だった（費用がほぼ 0 で、これから先の変更も見るため）。

## 決定（2026-11-24 にユーザーが選んだ）

- CodeQL は入れない。roadmap の S-2 は「入れない」として閉じる
- 推奨と比べて変わること：書き方で分かる欠陥を、毎回機械で拾う網が1枚減る。拾う役目は `/code-review` と `access-reviewer`（どちらも AI が読むレビュー）だけになる。公開の後に AI がコードを書き足すときも同じ

## 結果と注意

- 見直す条件：公開の後に、書き方で分かる欠陥（XSS、注入など）が本番で見つかったとき、またはコードを書く人が増えたとき
- リポジトリは公開のままにする（2026-11-24 に確かめた：履歴に秘密の値はなく、コミットのメールアドレスは GitHub の伏せ字だけ。非公開にすると secret scanning と push protection が有料になる）
