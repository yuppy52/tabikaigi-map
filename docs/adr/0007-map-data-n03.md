# ADR 0007：地図データに国土数値情報（行政区域）を使う

状態：決定（2026-10-16）

## 背景

都道府県の形は、モックのときから [dataofjapan/land](https://github.com/dataofjapan/land) の `japan.topojson`（元は国土地理院の地球地図日本）を簡略化して使っていた。LICENSE を決めるとき（2026-10-16）に条件を調べると、次のことが分かった。

- dataofjapan/land には LICENSE がなく、README に「非営利なら出典を書く。営利なら、出典に加えて地球地図日本への利用の報告」とだけある
- 国土地理院のいまの公式のページでは、地球地図日本には国土地理院のコンテンツ利用規約が適用され、「商用・非商用に関わらず出典を書く」とだけある。報告の決まりは見当たらない（README が古い可能性が高い）
- このアプリは、使われ始めたら広告を入れる予定（Q-029）。営利として扱う前提で、条件を言い切れる地図データにしたい

## 選択肢

| | A：いまのまま（dataofjapan/land） | B：国土数値情報 N03（行政区域、2025年版） | C：Natural Earth（admin-1） |
|---|---|---|---|
| 広告付きで使えるか | 使えるはず。ただし配布元と国土地理院の条件が食い違い、どちらに従えばよいかを公式の文書1つで言い切れない | 公式に「商用利用も可能」（CC BY 4.0 互換の約款）。報告は要らない | 使える（パブリックドメイン） |
| 出典 | 「© 国土地理院」 | 公式の文例がある（下） | 要らない |
| 手間 | 出典の文言を直すだけ | 約600MB を1回落とし、変換のスクリプトを1つ足す | 小さい。ただし日本の47都道府県がそろうか、形の細かさが足りるかを確かめていない |

## 決定

**B（国土数値情報 N03）**。2026-10-16 にユーザーと決めた（推奨案。ユーザーが Qiita の記事から見つけた）。

理由：広告を入れても使えることと、出典の書き方を、配布元の公式の文書で確かめられるのは B だけだった。A は条件の食い違いが残り、C は形の細かさを確かめる手間が B と変わらない。

## 作り方

- `tools/` で `npm run fetch-n03`（全国のデータ `N03-20250101_GML.zip` を落とし、都道府県単位の `N03-20250101_prefecture.geojson` だけを取り出す。リポジトリには入れない）→ `npm run gen-n03`（`tools/gen-n03.mjs`：県コードで島をまとめ、全国の地図で見えない小さな島を捨て、県の境目を共有する TopoJSON にして間引く）→ `npm run gen-map`（いままでどおり SVG のパスにする）
- 足した部品は `topojson-server` だけ（同じ作者の小さな部品）。都道府県の境目でまとめる道具として mapshaper も試したが、部品が229個増え、非推奨の警告（バッファの読み過ぎの恐れ）が出たのでやめた。N03 には都道府県単位にまとめたデータが入っているので、まとめる処理そのものが要らなかった
- 出来上がりは `tools/paths.json` で約85KB（前の地図データは約97KB）。見た目は前とほぼ同じ

## 結果と注意

- 出典を、画面（[screens](../design/screens.md) の「画面のルール」）、README、[NOTICE.md](../../NOTICE.md) に書く。公式の文例：「出典：国土交通省国土数値情報ダウンロードサイト（https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2025.html）」。加工したことを別に書き、国が作ったように見せない
- N03 のページに「測量法に基づく国土地理院長承認（複製）」とある。加工した形を使うときに手続きが要るかは確かめきれていない（要確認。公開の前に国土数値情報の問い合わせ窓口で確かめる）
- 広告を始めるときに、約款の最新の版を見直す（2026-03-23 施行の版が出ている）
- 新しい年度の N03 に替えるのは、県の形が変わったときだけでよい（全国の地図では年度の差はほぼ見えない）
