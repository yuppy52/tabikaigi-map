# ADR 0012：リアルタイムのつなぎ直しは自分で書き、WebSocket が通らない回線の予備の問い合わせは MVP では作らない

状態：決定（2026-10-26）

- 関係する要件：NFR-003（リアルタイム）、NFR-012（無料枠を超えたら止まる）、NFR-014（運営者1人で回せる）
- [ADR 0003](0003-backend-selection.md) の「リアルタイムの共有」のうち、「`partysocket` を使うかは Phase 2 で決める」を決め、「予備の問い合わせ」を MVP では作らないことにする（ADR 0003 のその部分を置き換える）

## 背景

Phase 2 のリアルタイムの項目を始めるときに、ADR 0003 で先送りしていた2つを決めた。

1. 画面が部屋（Durable Objects）につなぎ直す仕組みを、自分で書くか、部品（`partysocket`）を入れるか
2. WebSocket が通らない回線（会社の回線など）のときだけ、10〜15秒ごとに問い合わせる「予備」を作るか。ADR 0003 は作ると決めたが、「どの応答で通らないと見分けるか」は決めていなかった

## 決定（2026-10-26 にユーザーが推奨どおりに選んだ）

1. **つなぎ直しは部品を入れずに自分で書く**（試作 `spike/` で書いた形）。部品が増えず、版上げの手入れも要らない。ボット対策のウィジェット（4-1）と同じ考え方
2. **予備の問い合わせは MVP では作らない**。つながらないときは、画面の帯「自動で更新されていません［読み直す］」で、手で読み直してもらう（NFR-003 の「つながらないときは開き直したときの反映に戻る」の範囲）
   - 理由：友達どうしの会議は、たいていスマホの回線か家の Wi-Fi で、WebSocket が通らない場面は少ない見込み。見分け方を決めずに作ると、ふつうの切断でも予備に切り替わり、10〜15秒ごとの問い合わせで Workers と D1 の枠を使う
   - 公開した後に、友達から「更新されない」と言われたら、見分け方を決めて作る

## 決めた数字（2026-10-26 にユーザーと決めた。設計の「数秒」「だんだん長く」を数字にした）

| 何か | 値 |
|---|---|
| つながらないと分かってから帯を出すまで | 5秒 |
| つなぎ直す間隔 | 1・2・4・8・16・32秒、その後は60秒ごと |
| 自動でつなぎ直すのをやめるまで | 続けて10回失敗したら（約5分）。その後は帯の「読み直す」か、画面に戻ったとき（`visibilitychange`）にだけつなぐ |
| 最初のメッセージ（グループID）を送らない接続を切るまで | 10秒（部屋のアラーム） |
| 生きているかの確認（`ping`）を送る間隔 | 30秒（部屋を起こさない自動応答 `setWebSocketAutoResponse`） |

## 結果と注意

- 会社の回線などで WebSocket が通らない人は、開き直すか「読み直す」を押すまで、ほかの人の変更が見えない（requirements の NFR-003 の範囲内）
- 数字は仮の値。本番で、Durable Objects の回数と動いている時間（GB 秒）を測って見直す（roadmap の「基本設計で Phase 2 に回した確かめ」）
