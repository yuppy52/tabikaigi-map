# ADR 0017：Strix は使わず、公開の前に `access-reviewer` で全体を1回見直す（ADR 0015 の残りを覆す）

状態：決定（2026-11-24）

- 関係する要件：NFR-006（アクセス制御は保存先の側で守る）、NFR-009（費用に上限がある構成）
- [ADR 0015](0015-pre-launch-security-tools.md) の決定 2〜5（Strix を Muse Spark 1.3 と OpenRouter の前払いで動かす）を覆す。決定 1（CodeQL）は [ADR 0016](0016-no-codeql.md) で覆してある。これで ADR 0015 の決定はすべて覆した

## 背景

ADR 0015 の後、Strix の用意（roadmap の S-3）の手順を出したところで、ユーザーから「自分のサービスに攻撃するのはもういい」と言われた。用意には、OpenRouter のアカウントと $10 の前払い、Docker・Python 3.12・pipx を Mac に入れることが要り、まだ何も入れていなかった。

## 選択肢

| | Strix を使う（推奨だった） | 使わず、`access-reviewer` で全体を1回見直す（決定） |
|---|---|---|
| 確かめ方 | AI が手元の `wrangler dev` を実際に攻撃して、破れるかを試す | AI がコードと設定を読んで、抜け道を探す |
| 費用 | OpenRouter の前払い $10（手数料込みで $10.55） | 0 |
| 手間 | アカウント、鍵、Docker などを入れる。動かすたびに、リポジトリのコピーや手元の D1 の作り直しが要る | 指摘を直すだけ |
| 見落とし | 読むレビューとは別の目（動かして確かめる）が1枚増える | 読むレビューとテストだけ |

推奨は「使う」だった（読むレビューとテストの両方が同じ抜けを見落としても、動かして見つけられるため）。

## 決定（2026-11-24 にユーザーが選んだ）

- Strix は使わない。OpenRouter・Docker・pipx は入れない
- 代わりに、公開の前に `access-reviewer` に、API・D1 の制約・部屋（WebSocket）・配信の設定の全体を通しで1回見てもらい、指摘を直す。これまでは変更ごとに頼んでいて、全体を通しで見たことはなかった
- 推奨と比べて変わること：動かして確かめる網がなくなる。読むレビューとテストの両方が同じ抜けを見落とすと、公開の後まで気づけない

## 結果と注意

- `.gitignore` の `strix_runs/` は消す
- 見直す条件：公開の後に、レビューとテストで見落とした認可の抜けが見つかったとき、または友達以外にも使われ始めたとき（広告を入れるときなど）
