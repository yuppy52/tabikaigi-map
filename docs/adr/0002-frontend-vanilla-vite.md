# ADR 0002：画面は素の JavaScript ＋ Vite で作る

- 状態：**置き換え**（2026-10-04 に [ADR 0004](0004-frontend-react-typescript.md) で、React ＋ TypeScript ＋ Vite に置き換えた。ユーザーが JavaScript に慣れておらず TypeScript を使うことになり、モックのコードをそのまま使う理由がなくなったため）
- 日付：2026-09-27

## 背景

モックは HTML 1ファイル（`tools/template.html`）に、地図データを埋め込んで作っている。画面の数が増え（[screens.md](../design/screens.md)）、Firebase の SDK を使うようになるので、画面をどう作るかを決める。

## 選択肢

|                              | 素の JS（CDN から SDK を読む）   | **素の JS ＋ Vite**      | React / Vue など ＋ Vite |
| ---------------------------- | -------------------------------- | ------------------------ | ------------------------ |
| モックからの移行             | そのまま                         | ファイルを分けるだけ     | 書き直し                 |
| Firebase SDK                 | CDN（tree-shaking が効かず重い） | npm（必要な分だけ入る）  | npm                      |
| 本番とエミュレータの切り替え | 手で書く                         | 環境変数で切り替えられる | 環境変数で切り替えられる |
| 画面が増えたときの書きやすさ | 苦しい                           | まあまあ                 | 良い                     |
| 学ぶこと                     | なし                             | Vite だけ                | フレームワーク           |

## 決定

**素の JavaScript ＋ Vite** を使う。

- モックの描画のコード（地図、一覧、シート）をほぼそのまま使える
- 画面は十数個で、状態もグループ1つ分と小さいので、フレームワークなしでも書ける
- ルールのテストのためにどうせ npm を入れるので、Vite を足す手間は小さい

## 影響

- 画面が増えて書きにくくなったら、フレームワークへの移行を別の ADR で検討する
- 地図データを埋め込む今のビルド（`tools/build.mjs`）は、Vite で JSON を import する形に置き換える
