# ADR 0004：画面は React ＋ TypeScript ＋ Vite で作り、検索に出すページは素の HTML にする

- 状態：**決定**（2026-10-04、ユーザーと決めた）
- 日付：2026-10-04
- [ADR 0002](0002-frontend-vanilla-vite.md)（素の JavaScript ＋ Vite、提案中）を置き換える
- 関係する要件：NFR-001（端末）、NFR-002（アプリ内ブラウザ）、NFR-008（プライバシーポリシーのページ）、NFR-005（グループIDを知らなければ見られない）、NFR-016（表示の速さ）、NFR-019（検索に出す：2026-10-04 追加）

## 背景

ADR 0002 は「モックの描画のコードをほぼそのまま使える」ことを理由に、素の JavaScript を選んでいた。2026-10-04 に、次の3つが分かった。

- ユーザーは JavaScript の書き方をよく知らず、TypeScript で書いてほしい（型があるほうが間違いに気づきやすく、読みやすい）。モックはどのみち書き直しになるので、ADR 0002 の理由がなくなった
- ユーザーは検索で上位に出てほしい（SEO）。ADR 0003 の調査を頼むときに「SEO は不要」と書いたのは、確かめていない思い込みだった
- バックエンドは [ADR 0003](0003-backend-selection.md) で案 C（Cloudflare Workers＋D1、API は Hono）を第一候補にした（提案中）

## 選択肢

| | 素の TypeScript ＋ Vite | **React ＋ TypeScript ＋ Vite** | Next.js |
|---|---|---|---|
| 学ぶこと | Vite、画面を直接書き換える作法 | JSX（HTML に近い書き方）、状態（`useState`）、部品（コンポーネント） | React に加えて、ルーティング、サーバーとブラウザの区別、書き出しの制約 |
| 画面が増えたとき | 「データが変わったら画面のどこを直すか」を自分で書くので、直し忘れの不具合が増えやすい | データから画面を作るので、ずれにくい | 同左 |
| 調べたときの情報 | 少なめ | 非常に多い | 多い |
| SEO | 検索に出すページを素の HTML にすれば強い | 同左 | サーバーで HTML を作れるのが強みだが、このアプリでは下の理由で使いにくい |
| Cloudflare の無料枠 | 静的ファイルなので無料・無制限 | 同左 | サーバーで画面を作ると、開くたびに Worker の枠（1日10万）を使う。静的に書き出すと、招待URL `/g/<グループID>` を素直に作れない（[ADR 0003](0003-backend-selection.md) の調査） |
| 大きさ | 最小 | React の分が増える（数十KB。要確認：作って測る）。NFR-016 の3秒には収まる見込み | さらに増える |

## 決定

**アプリの画面（グループの地図、設定、マイページなど）は React ＋ TypeScript ＋ Vite で作る。検索に出すページ（トップ、使い方、プライバシーポリシー）は、中身を書いた素の HTML にする。API を自分で書く構成（[ADR 0003](0003-backend-selection.md) の案 C）になった場合は、API も TypeScript で書く。**

- 画面のデータ（行った県、メンバー、表示の切り替え）が変わると、地図・数・一覧など画面のあちこちが変わる。React は「データから画面を作る」書き方なので、直し忘れの不具合を防ぎやすい
- 検索エンジンにとって一番強いのは、中身が書かれた HTML がすぐ返ってくること。検索に出したいページは固定の文章なので、素の HTML で十分。Vite は複数の HTML ページを作れる
- Next.js は、SEO の利点が上の方法で代えられ、Cloudflare の無料枠や招待URLと相性が悪く、学ぶことが一番多いので選ばない

### 検索に出す・出さない（NFR-019）

| ページ | 検索に出すか |
|---|---|
| トップ（アプリの説明）、使い方、プライバシーポリシー | 出す。タイトル・説明文・OGP・sitemap を用意し、Google Search Console に登録する |
| グループの地図（`/g/<グループID>`）と、アプリの中の画面 | **出さない**（`noindex`）。招待URLを知っている人だけの場所なので（NFR-005） |

検索の入口のページを、トップ・使い方・プライバシーポリシーのほかに足すか（例：都道府県ごとのページ）は、MVP の後に考える。利用者の集計を出すページはプライバシーの扱いを決めてから。

## 影響

- モックの画面（`tools/template.html`）は React の部品に書き直す。地図の形のデータ（`tools/paths.json`）はそのまま使う
- CLAUDE.md の「画面は素の JavaScript ＋ Vite」を直す
- ADR 0002 の状態を「置き換え（ADR 0004）」にする
- 検索で上位に出るかは、技術より中身（説明の文章、使い方の例）で決まる。上位を約束するものではない
