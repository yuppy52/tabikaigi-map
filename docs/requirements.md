## この文書について

- 利用者から見た「何ができるか」を書く。どう作るかは [design/](design/) に書く
- 機能要件は `REQ-001`、非機能要件は `NFR-001` の形で番号を振る。**一度振った番号は振り直さない**（なくした要件は欠番にする）。design や adr からは「（REQ-012）」のように参照する
- 「UC」の列は、元になった [ユースケース](use-cases.md) の番号
- 言葉は [用語集](glossary.md) にそろえる。決まっていないことは「（要確認：Q-xxx）」と書き、[open-questions.md](open-questions.md) で管理する

## 目的

友達グループで「今まで行ったことのある都道府県」を日本地図に塗って共有し、全員まだ行っていない県を見つけて、次の旅行先を決めやすくする。

## 利用者

- 友達同士の小さなグループ（1グループ最大20人）
- スマホで使う。招待URLは主に LINE で送られる
- 運営者（このアプリを作って動かす人。1人）

## 2つの使い方

ログインせずに名前だけで使うこともでき、ログインして使うこともできる。違いのまとめ（詳しくは各要件）：

| | ログインなし | ログインあり |
|---|---|---|
| 入り方 | グループごとの招待URL | 招待URL、またはグループ一覧 |
| 名前 | グループごとに入力する | グループごとに入力する |
| 名前の変更 | できない | 本人だけできる |
| グループの切り替え | なし | あり |
| 「行った」 | グループのメンバーごとに持つ | アカウントに保存し、全グループに同期する |
| 編集できる人 | そのグループの誰でも | 本人だけ |

### ログインなしで参加していた人がログインしたとき

| ID | 要件 | UC |
|---|---|---|
| REQ-037 | ログインなしでグループに参加していた人が、そのグループを開いたままアカウントを作る・ログインすると、そのグループのメンバーをアカウントに紐づける。そのメンバーが作成者のメンバーなら、ログインした人が作成者として設定を変えられるようになる | UC-08・UC-17 |
| REQ-038 | 紐づけるときの「行った」は、下の表のように扱う | UC-09 |
| REQ-039 | 開いていたグループに、自分のアカウントのメンバーがすでにいる（別の端末で参加済み）ときは、いま入っていたメンバーは紐づけない。その「行った」を REQ-038 と同じ流れでアカウントに合わせてから、そのメンバーを消す。**1つのグループで、1つのアカウントに紐づくメンバーは1人だけ** | UC-08 |
| REQ-040 | 同じ端末からログインなしで参加していた他のグループは、ログインしたときには何もしない。次にそのグループを開いて名前を入れたときに、REQ-041〜REQ-043 の流れになる（暫定。要確認：Q-005・Q-017） | UC-08 |

REQ-038 の扱い。グループでの「行った」を G、アカウントの「行った」を U とする。

| 状況 | 挙動 |
|---|---|
| U が空（このアカウントでまだ「行った」を保存していない） | 確認なしで G をアカウントに引き継ぐ |
| G が U にすべて含まれている | 確認なしで U を表示する |
| それ以外 | 確認を出す（下） |

> アカウントに保存されている「行った」（N県）をこのグループに反映しますか？
> - **アカウントのデータを使う**：このグループでの入力は破棄する
> - **合算する**：G と U を合わせてアカウントに保存する（参加中の他のグループにも反映される）

| REQ-042 | まだそのグループのメンバーでなければ、名前を入力してもらう（アカウントの表示名は使わない）。同じ名前のメンバーがいなければ、新しいメンバーとして参加する | UC-02 |

| ID | 要件 | UC |
|---|---|---|
| REQ-044 | **管理できる人**（メンバーの削除、グループ名の変更、グループの削除ができる人）を、グループごとに「誰でも」（初期値）か「作成者のみ」から選べる | UC-13 |
| REQ-045 | 管理できる人を変えられるのは、ログインしている作成者だけ（ログインなしでは、名前を入れれば誰でも作成者になれてしまうため）。作成者がいないグループでは、誰も変えられない | UC-13 |
| REQ-046 | 管理できる人は、グループ名を変えられる | UC-14 |
| REQ-047 | 管理できる人は、グループを削除できる。削除の前に確認する。メンバーへの通知はしない。ログインしているメンバーのアカウントの「行った」は残る | UC-14 |
| REQ-048 | 管理できる人は、ほかのメンバーをグループから削除できる。削除されたメンバーのグループでの「行った」は消える。アカウントの「行った」は消えない | UC-15 |
| REQ-049 | メンバーは、管理できる人の設定に関係なく、自分でグループから退出できる。グループでの「行った」は消える。アカウントの「行った」は残る | UC-16 |
| REQ-050 | 最後の1人が退出するときは、「グループも削除されます」と確認し、グループも削除する（退会で最後の1人が抜けるときも同じ） | UC-16・UC-18 |
| REQ-051 | 作成者のメンバーがいなくなったら（退出、削除、退会）、そのグループの作成者はいなくなり、管理できる人は「誰でも」に変わる。以後「作成者のみ」には誰も変えられない | UC-15・UC-16・UC-18 |
| REQ-052 | 作成者は「作成者のメンバー」で決まる（名前やアカウントでは決まらない）。ログインなしの作成者は、作成者の名前で入れば作成者として操作でき、ログインすると管理できる人を変えられる（REQ-045） | UC-13 |

### 分かっている限界（信頼ベースのため受け入れる）

- 本人確認（REQ-043）は自己申告で、本当に本人かは確かめていない。ログインしていない作成者のメンバーを、先に別の人が自分のものにすると、その人が作成者になる。ただし初期値の「誰でも」では、もともと誰でもメンバーやグループを削除できるので、増える被害は「作成者のみ」に変えてほかの人を締め出せることだけ。起きたらグループを作り直してもらう
- メンバーを削除しても、招待URLは変わらない（再発行しない）ので、その人はまた参加できる。削除は「追い出す」ためのものではない
- ログインしていないメンバーは、「作成者のみ」の設定でも、その名前で入れば誰でも退出させられる（本人を区別できないため。仕組みは基本設計で決める：要確認：Q-018）

| ID | 要件 |

### セキュリティと個人情報

| ID | 要件 |
|---|---|
| NFR-005 | グループIDは推測できない文字列にし、グループの一覧は誰も取得できないようにする |
| NFR-006 | 機能要件で決めた「誰が何をできるか」（本人しか編集できない、管理できる人だけが削除できる、など）は、画面を改造されても破られないように、データの保存先の側で守る |
| NFR-007 | 扱う個人情報は、メンバーの名前、メールアドレス（ログインする人）、行った都道府県だけにする。ログインしている人は、退会すればこれらを消せる（REQ-036） |
| NFR-008 | プライバシーポリシーを公開し、どの画面からもすぐ（1回の操作で）開けるようにする。運営者と問い合わせ先、扱う情報と使い道、外部のサービスに送る情報と送り先（データの保存、ログイン、アクセス解析、エラーの把握、広告など）、消し方・消してほしいときの頼み方を書く。名前やメールアドレスを入れる画面からも、使い道が分かるようにする（法律上どこまで必要かは要確認：Q-028） |

### 信頼性

| ID | 要件 |
|---|---|
| NFR-009 | 保存に失敗したとき（通信エラー、混み合っているなど）は、利用者にそのことを伝える。付け外しした「行った」が、黙って失われないようにする |

### 運用

運営者が、アプリが使われているか、無料枠に収まっているか、壊れていないかを、友達からの報告を待たずに知るための要件。

| ID | 要件 |
|---|---|
| NFR-010 | **利用状況の把握**：運営者は、グループの数、メンバーの数（ログインあり・なし別）、最近使われたグループの数（例：直近30日に開かれた）を確かめられる。使われているかを知ることと、無料枠の見積もりに使う。人数や回数の集計で足り、利用者一人ひとりの行動は追わない。グループ名、メンバーの名前、誰がどこへ行ったかは、集計のために外部のサービスへ送らない（方法は要確認：Q-025） |
| NFR-011 | **無料枠の監視**：運営者は、使っているサービスの使用量が無料枠のどのくらいかを確かめられる。上限に近づいたら（例：8割）、運営者に知らせが届く（方法は要確認：Q-026） |
| NFR-012 | **無料枠を超えたとき**：サービスが止まったときは、利用者に「いまは使えない」ことが分かる表示を出す（NFR-009）。止まる前に保存したデータは失われない。無料枠が戻れば（翌日・翌月など）、そのまま使える |
| NFR-013 | **エラーの把握**：利用者の画面で起きたエラー（保存の失敗、画面が動かないなど）を、運営者が把握できる。エラーの記録には、メンバーの名前、メールアドレス、行った都道府県を含めない（方法は要確認：Q-027） |
| NFR-014 | **運用の手間**：運営者1人で回せる形にする。ふだんの確認は短時間で済み、確かめる場所はできるだけ少なくまとめる（何かあったときは知らせが届き、そのときだけ詳しく見る） |

## やらないこと（MVP）

- 招待URLの再発行
- グループごとに内容が変わるリンクのプレビュー（OGP は全グループ共通）
- 市区町村単位、訪問日、写真
- 行き先の投票などの「決める」機能
- 匿名の利用者の記録の自動削除。使われなくなったグループも残り続ける（最後の1人が退出したときにグループを削除するのは、退出の操作の一部として行う）
- メンバーの色の変更
- 利用者一人ひとりの行動の追跡（利用状況は集計だけを見る。NFR-010）
