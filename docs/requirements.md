## この文書について

- 利用者から見た「何ができるか」を書く。どう作るかは [design/](design/) に書く
- 機能要件は `REQ-001`、非機能要件は `NFR-001` の形で番号を振る。**一度振った番号は振り直さない**（なくした要件は欠番にする）。あとから足した要件は、番号の順ではなく、内容の合う節に置く。design や adr からは「（REQ-012）」のように参照する
- 「UC」の列は、元になった [ユースケース](use-cases.md) の番号
- 言葉は [用語集](glossary.md) にそろえる。決まっていないことは「（要確認：Q-xxx）」と書き、[open-questions.md](open-questions.md) で管理する

## 目的

友達グループで「今まで行ったことのある都道府県」を日本地図に塗って共有し、全員まだ行っていない県を見つけて、次の旅行先を決めやすくする。

## 利用者

- 友達同士の小さなグループ（1グループ最大20人）
- スマホで使う。招待URLは主に LINE で送られる
- 運営者（このアプリを作って動かす人。1人）

## ログインはない

全員が、招待URLと名前だけで使う。ログイン（アカウント、グループ一覧、「行った」の全グループへの同期、作成者だけが管理できる設定）は作らない（2026-11-06 にユーザーと決めた：[ADR 0013](adr/0013-drop-login.md)。預かる情報と、運営者が受ける対応を減らすため）。それまでは「ログインなし」と「ログインあり」の2つの使い方を書いていた。なくした要件は「なくした要件」の節に並べる。

### 分かっている限界（信頼ベースのため受け入れる）

- 名前は自己申告で、本人かどうかは確かめない。参加の画面で名前を選べば、誰でもその人として入れる（REQ-012・REQ-022）
- 文字の種類が違うのに見た目がそっくりな名前（英字の「a」とロシア文字の「а」など）は、別の名前として作れる。参加の画面の一覧で同じ名前が2人いるように見えることがある。わざと紛らわしくしても、できることは名前を選べば誰でもできることと同じなので、守りは足さない（2026-11-10 にユーザーが推奨どおりに決めた。REQ-009 の「見た目が同じ別の名前を作れない」は、見えない文字と絵文字の形の違いのこと）
- 招待URLを知っている人は誰でも、メンバーの削除、グループ名の変更、グループの削除ができる。ほかの人を締め出す設定はない（2026-11-06：ADR 0013。それまでは、ログインした作成者が「作成者のみ」にできた）。削除の前の確認で打ち間違いは防ぐが、わざと消されたら戻せないので、グループを作り直してもらう
- メンバーを削除しても、招待URLは変わらない（再発行しない）ので、その人はまた参加できる。削除は「追い出す」ためのものではない
- 招待URL（グループID）を知っている人は、参加しなくても、メンバーにできることはすべてできる（地図を読む、リアルタイムの知らせを受ける、「行った」の付け外し、退出、管理の操作）。保存先から見て、メンバーかどうかを見分けられないため。招待URLを知っていれば参加して同じことができるので、増える被害はない（2026-10-11。[権限マトリクス](design/permissions.md)）
- 誰でも参加して書き込めるので、悪意のある人や不具合が無料枠を使い切ると、無料枠が戻るまで（翌日など）全員が使えなくなる（NFR-012）。請求は来ない。防ぐ手立て（連続したアクセスを止める、ボット対策、ファイルがない URL で枠を使わせない）は入れるが、完全には防げない（2026-10-12：Q-031。[architecture](design/architecture.md) の「無料枠を使い切られないために」）
  - リアルタイムの共有（NFR-003）は、自分でグループを作った人なら、その日の分の枠を使い切って止められる。止まるのはリアルタイムだけで、保存と開き直しはできる（2026-10-26）
- 同じ回線（会議の場の Wi‑Fi、携帯会社の共有の回線）から続けて操作すると、使い切られる対策（連続したアクセスを止める）に当たって、10秒ほど保存できないことがある。そのときは「少し待ってもう一度」と出す（2026-10-12：Q-031 の `/review-docs` #2）
- エラーの把握のサービスに送る鍵は画面に入っていて誰でも見られるので、偽のエラーを大量に送られると、その月はエラーを把握できなくなる（請求は来ない。2026-10-12：Q-027）
- 利用が増えて無料枠（1日あたりの回数など）を超えたときも、その日は保存やリアルタイムの反映が止まり、翌日に戻る。有料プランは上限なく請求が来るので使わない（NFR-004）。これを受け入れる（2026-10-04 にユーザーと決めた）。本当に利用が伸びたら、そのときに構成を考え直す
- 利用者が削除したグループやメンバーは、戻せない（NFR-017）。削除の前の確認で防ぐ
- 参加する前に見えるのはグループ名とメンバーの名前だけ（REQ-002）だが、これは画面の側の決まりで、保存先では守らない。改造した画面なら参加する前でも地図を読めるが、招待URLを知っていれば参加して見られるので、増える被害はない
- 端末に覚えた名前（REQ-024）は、iPhone・Mac の Safari（iPhone の Chrome も同じかは要確認）では、しばらく開かないと消えることがある（ブラウザの追跡防止のため）。消えたら、参加の画面で自分の名前を選び直す（REQ-012）（2026-10-12：Q-017）
- 端末が覚えているメンバーは、「メンバーを変更する」（REQ-056）か退出で忘れるまで残る。ブラウザのサイトデータを消しても忘れる。共用の端末では、使い終わったら「メンバーを変更する」で忘れてもらう（2026-10-12 にユーザーと決めた。ログアウト・退会のくだりは 2026-11-06 に消した）

| NFR-016 | **表示の速さ**：スマホの回線で、招待URLを開いてから地図が出るまで3秒以内を目安にする |
| NFR-020 | **独自ドメイン**：最初から独自ドメインを使い、変えない（ドメインを変えると、全員が参加の画面で名前の選び直しになり、検索の評価も引き継がれにくい（要確認）ため）。年額の決まった費用で、ユーザーと相談して決めた（2026-10-04。NFR-004、[ADR 0003](adr/0003-backend-selection.md)） |

### 運用

運営者が、アプリが使われているか、無料枠に収まっているか、壊れていないかを、友達からの報告を待たずに知るための要件。

| ID | 要件 |
|---|---|
| NFR-010 | **利用状況の把握**：運営者は、グループの数、メンバーの数、最近使われたグループの数（例：直近30日に開かれた）を確かめられる。使われているかを知ることと、無料枠の見積もりに使う。人数や回数の集計で足り、利用者一人ひとりの行動は追わない。グループ名、メンバーの名前、誰がどこへ行ったか、**招待URL（グループID）**は、集計のために外部のサービスへ送らない（招待URLを知れば誰でも参加できるため。外部に送るページのURLからはグループIDを伏せる）（方法：保存しているデータから数え、外部のアクセス解析は使わない。「最近」は直近30日に開かれたもの。2026-10-12：Q-025） |
| NFR-011 | **無料枠の監視**：運営者は、使っているサービスの使用量が無料枠のどのくらいかを確かめられる。MVP では、運営者が週1回確かめる。上限に近づいたことを自動で知らせる仕組みは、1日の上限の5割を超えた日があったら作る（それまでは作らない。ふだんの使い方では1割以下の見込みのため）。上限に達したときは、使うサービスからメールが届くもの（データベース）がある（2026-10-12：Q-026、`/review-docs` #11） |
| NFR-012 | **無料枠を超えたとき**：データの保存や読み込みが止まったときは、利用者に「いまは使えない」ことが分かる表示を出す（NFR-009）。止まる前に保存したデータは失われない。無料枠が戻れば（翌日・翌月など）、そのまま使える。画面の配信そのものが止まったときは表示を出せないので、この要件の対象外とする（Q-026） |
| NFR-013 | **エラーの把握**：利用者の画面で起きたエラー（保存の失敗、画面が動かないなど）を、運営者が把握できる。エラーの記録には、メンバーの名前、メールアドレス、行った都道府県、招待URL（グループID）を含めない（方法：エラー収集のサービス（Sentry の無料プラン）に、グループIDを伏せて送る。2026-10-12：Q-027） |
| NFR-014 | **運用の手間**：運営者1人で回せる形にする。ふだんの確認は短時間で済み、確かめる場所はできるだけ少なくまとめる（何かあったときは知らせが届き、そのときだけ詳しく見る。知らせは、エラーの把握のサービスのメールと、データベースの上限に達したときのメール。2026-10-12）。MVP では運営者用の管理画面は作らず、使用量は使うサービスの管理画面と知らせで、利用状況は運営者が手元で動かす集計で確かめる。管理画面は MVP の次に作る（中身と作り方は 2026-10-12 に Q-030 で決めた） |
| NFR-018 | **削除の依頼への対応**：利用者は、問い合わせ用のフォームから、データを消してほしいと頼める（運営者の個人のメールアドレスは公開しない）。フォームはアプリの中に作る（2026-10-04 にユーザーと決めた。外部のサービスに送らないので、プライバシーポリシーの送り先は増えない）。返事や確認のメールは、運営者の個人のアドレスではなく、このアプリ用に作ったアドレスから送る。本人の確かめ方：招待URLとメンバーの名前を教えてもらえれば消す（招待URLを知っている人なら、アプリの中でも同じことができるため）。頼まれてから1か月以内に応じる。返信先のメールアドレスは任意（なくても受け付ける。返事が要らない依頼や、アドレスを預けたくない人のため。ログインをやめて、アプリが預かるメールアドレスはここだけになったので、2026-11-06 にユーザーと決めた：ADR 0013）。ふだんは利用者が自分で消せる（退出 REQ-049、グループの削除 REQ-047）ので、これは例外のときのため |

## やらないこと（MVP）

- 招待URLの再発行
- グループごとに内容が変わるリンクのプレビュー（OGP は全グループ共通）
- 市区町村単位、訪問日、写真
- 行き先の投票などの「決める」機能
- 使われなくなったグループの自動削除。使われなくなったグループも残り続ける（最後の1人が退出したときにグループを削除するのは、退出の操作の一部として行う）
- メンバーの色の変更
- ログイン（アカウント、グループ一覧、「行った」の全グループへの同期、作成者だけが管理できる設定、自分の名前の変更）。要るようになったら新しい ADR で足す（2026-11-06：[ADR 0013](adr/0013-drop-login.md)）
- 利用者一人ひとりの行動の追跡（利用状況は集計だけを見る。NFR-010）
- 運営者用の管理画面（ダッシュボード）。多くの人に使ってもらえるかを確かめるため、MVP の次に作る（NFR-014、Q-030）
- 外部のアクセス解析（利用状況は保存しているデータから数える。NFR-010、Q-025）
- 自動の定期バックアップと、利用者が削除したデータの復元（NFR-017）
- 広告。友達以外にも使われ始めてから検討する（Q-029）。入れるときは、プライバシーポリシー（NFR-008）に送り先などを書き足し、外部送信規律への対応を確かめる。画面は、あとから広告を置く場所を足せる余地を残しておく
