## この文書について

- 「誰が・何を・できるか」と「それをどこで守るか」を、操作ごとに並べる。決まりの正本は requirements の各要件で、ここはその一覧
- 「守る場所」の書き方：
  - **API**：Hono の API が、書き込む SQL の `WHERE`（条件付きの `UPDATE` を含む）や ID トークンで確かめる（形は [data-model.md](data-model.md) の「設計のポイント」）
  - **制約**：D1 の `UNIQUE`・`CHECK`・外部キー・トリガー
  - **画面**：画面だけの決まり。改造した画面なら破れる（破れても増える被害がないものだけ。下の「画面だけで止めているもの」）
- 記号：
  - ○ できる
  - × できない。**API か制約で断る**（Phase 2 でテストする）
  - ×画 できない。ただし**画面だけで止めている**（API は通す。テストしない）
  - — その立場では起きない
- 〔未〕は、本物の D1 で動くかをまだ確かめていない守り方（トリガーと部分 `UNIQUE`。Phase 2 の最初に試し、使えなければ API とテストで守る：[ADR 0005](../adr/0005-owner-flag-on-member.md)）。〔未決〕は決まっていないもの

## 人の区別

言葉は [用語集](../glossary.md) にそろえる。

| 立場 | どういう人か |
|---|---|
| 来訪者 | まだそのグループに入っていない、ログインしていない人。招待URL（グループID）を知っている |
| ログインなしのメンバー | 名前で入っている人。**確認待ち**のアカウントの人もここに入る（NFR-006 (10)） |
| ログイン済み（まだ紐づいていない） | ログイン済みで、そのグループに自分に紐づいたメンバーがまだいない人。ログインした来訪者と、ログインなしのメンバーとして入っていてログインしたばかりの人（このあと紐づける：REQ-037・REQ-040） |
| 紐づいたメンバーの本人 | ログイン済みで、そのグループに自分に紐づいたメンバーがいる人 |
| 作成者のメンバー | グループを作ったときの最初のメンバー（`is_owner = 1`）。ログインなしのままのことも、紐づいていることもある（REQ-052）。下の「管理の操作」と「作成者の別の入口」で扱う |

### API から見える区別

API が確かめられるのは次のものだけ。

1. グループID（URL に入っている）
2. 送られてきたメンバーの番号
3. ID トークン（あれば）：`uid`、`email_verified`（確認済みか）、`auth_time`（最後にログインした時刻）

ログインなしの人は証明書を持たないので、API では「ログインなしのメンバー」と「来訪者」を見分けられない。そのため、ログインなしのメンバーに許す操作は、API の上では「グループIDを知っている人なら誰でも」できる。招待URLを知っていれば参加して同じことができるので、増える被害はない（requirements の「分かっている限界」）。

トークンが送られてきたのに確かめられない（期限切れ、署名の誤り、公開鍵が取れない）ときは、ログインなしに落とさずエラーを返す（[data-model.md](data-model.md) の「共通の決まり」）。

## 管理の操作

管理できる人（REQ-044）の設定ごとに分ける。「作成者のみ」が効くのは、`manage_by = 'owner'` で、かつ作成者のメンバーがいるときだけ（[data-model.md](data-model.md) の「作成者」）。

「作成者のみ」に変えられるのはログイン済みの作成者だけで（REQ-045）、紐づけを外す操作はなく、退会ではメンバーごと消える。そのため、**「作成者のみ」が効いている間、作成者のメンバーは必ず紐づいている**。「作成者のみ」の操作は、作成者のメンバーに紐づいた本人だけが通る（2026-10-11 にユーザーと決めた）。

| 操作 | 「誰でも」（初期値） | 「作成者のみ」 | 作成者がいなくなった後 | 守る場所 | 要件 |
|---|---|---|---|---|---|
| メンバーを削除する（紐づいたメンバーも含む） | メンバーなら誰でも（API の上では来訪者も） | 作成者のメンバーに紐づいた本人だけ | 「誰でも」と同じ | API（`manage_by` と、作成者のメンバーの `uid` が自分かを、同じ SQL の `WHERE` で確かめる） | REQ-048・REQ-051・NFR-006 (5) |
| グループ名を変える | 同上 | 同上 | 同上 | 同上 | REQ-046・NFR-006 (5) |
| グループを削除する | 同上 | 同上 | 同上 | 同上 | REQ-047・NFR-006 (5) |
| 管理できる人を変える | ログイン済みの作成者だけ（作成者のメンバーに紐づいた本人） | 同じ | 誰も変えられない | API（作成者のメンバーの `uid` が自分か。`email_verified`） | REQ-045・NFR-006 (4)(10) |
| 作成者を変える・付け足す | 誰もできない | 誰もできない | 誰もできない（作成者は戻らない） | 制約（部分 `UNIQUE` インデックス〔未〕、`is_owner` の更新と後からの印付きの追加を断るトリガー〔未〕） | REQ-051・REQ-052・NFR-006 (4)・[ADR 0005](../adr/0005-owner-flag-on-member.md) |
| 自分で退出する | ○ | ○（設定に関係なく） | ○ | 上の「退出させる」の2行 | REQ-049 |

「作成者のみ」にした作成者が来なくなると、そのグループは誰も管理できず、削除もできない。運営者も戻さない（2026-10-11 にユーザーと決めた。requirements の「分かっている限界」）。

## 作成者の別の入口

[data-model.md](data-model.md) の「作成者」の表のうち、別の入口から来る場面で、作成者として何ができるか（[learnings](../learnings/2026-10-02-owner-and-slot-lifecycle.md)）。

| 場面 | 作成者として何ができるか |
|---|---|
| ログインなしで、作成者のメンバーの名前で入る | 作成者のメンバーとして入れる（信頼ベース：REQ-052）。ただし作成者のメンバーが紐づいていないので「作成者のみ」にはできず、できるのは「誰でも」の操作だけ |
| 別の端末で別の名前で入り、そちらを紐づけた | 作成者のメンバーはログインなしで残る（REQ-039）。「作成者のみ」にはできない。戻すには、紐づいた別の名前のメンバーで退出し、作成者のメンバーの名前で入り直して紐づける（REQ-043）。ログアウトして作成者のメンバーで退出すると作成者は戻らないので、REQ-039 の知らせで注意する |
| ログアウトした | 紐づいた作成者のメンバーには、ログインなしでは入れない（REQ-013・REQ-035）。別の名前なら新しいメンバー（作成者ではない）として入れ、ログインし直すと REQ-039 になる。ログインし直して入れば作成者のまま |
| 退会の途中で失敗した（D1 は消え、Firebase のアカウントが残った） | メンバーは消えているので、作成者ではない。手元の ID トークン（最大1時間）で、グループを作る・参加する・アカウントの「行った」を保存することはできる（`accounts` の行が作り直される。害は小さいので受け入れる：[auth-flow.md](auth-flow.md) の 5.） |

## 運営者

運営者は、`wrangler` で D1 を直接読み書きできる（アプリの権限の外）。使うのはバックアップ（NFR-017）、削除の依頼への対応（NFR-018）、集計（NFR-010）のときだけにする。

## 画面だけで止めているもの

表の「×画」の欄。改造した画面なら破れる。

| 画面だけの決まり | 改造した画面でできること | 受け入れる理由 |
|---|---|---|
| 参加する前は地図を見せない（REQ-002） | 参加しないで地図（アカウントの「行った」を含む）を読める | 招待URLを知っていれば参加して見られる |
| 参加する前はリアルタイムにつながない | 参加しないで知らせを受けられる | 同上 |
| 紐づいていないメンバーの「行った」の付け外しと退出は、その名前で入った人がする（REQ-022・REQ-023） | 参加しないで、またはログイン済みの人が、付け外し・退出させられる | ログインなしは信頼ベースで、同じ名前を入れれば誰でもできる |
| 「誰でも」のときの管理の操作はメンバーがする | 参加しないで削除・名前の変更ができる | 招待URLを知っていれば参加して同じことができる |

どれも requirements の「分かっている限界」（招待URLを知っている人は、参加しなくても、ログインなしのメンバーにできることはすべてできる）に書いてある。
