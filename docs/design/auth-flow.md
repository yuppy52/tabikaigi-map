## 前提

- ログインはない。誰もが招待URLと名前だけで入る。API は証明書を受け取らない
- 端末には、グループごとに「覚えているメンバーの番号と名前」を持つ（下の「端末が覚えるもの」）

## 端末が覚えるもの（Q-017）

2026-10-12 にユーザーと決めた（調べた結果は `researcher` による。出典：https://webkit.org/tracking-prevention/ 、https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria）。

| 項目 | 決めたこと |
|---|---|
| 覚える中身 | グループIDごとに「メンバーの番号」と「名前」だけ。グループ名や「行った」は覚えない（毎回 API から読む） |
| 保存先 | ブラウザの `localStorage`（サーバーには送らない）。サーバーが付けるクッキーに端末の番号を持つ案は、作るものと権限の検討が増えるので採らない。Safari で入れ直す人が多いと分かったら見直す |
| 複数のグループ | グループIDをキーにして、グループごとに1人ずつ覚える |
| 覚えるとき | グループに入ったときはいつも、そのメンバーを覚え直す：名前を選んで入った、新しく参加した、「もういます」から入った、グループを作った。断られたとき・通信エラーのときは何も覚えない |
| 忘れるとき | 退出、グループの削除、「メンバーを変更する」（REQ-056）、開いたグループが見つからない、自分のメンバーが削除されていた、覚えていたメンバーが合わない（REQ-025）（[screens.md](screens.md) の「操作の後に開く画面」） |
| 共用の端末 | 使い終わったら「メンバーを変更する」で忘れてもらう（requirements の「分かっている限界」） |
| ブラウザごと | 覚えるものはブラウザごとに別（LINE のアプリ内ブラウザと Safari も別）。そのため LINE の中で開いたアプリの画面は、外部ブラウザで開き直す（[screens.md](screens.md) の「画面のルール」、NFR-002） |
| 書けないとき | シークレットモードや容量不足で `localStorage` に書けなくても、画面は止めない（読み書きを `try…catch` で包む）。覚えられないだけで、名前を入れれば使える |

2026-11-06 に「ログインの状態の目印」と「ログアウト・退会のとき」の行をなくした。

**Safari では消えることがある**：iPhone・Mac の Safari（iPhone の Chrome も同じかは要確認）は、Safari を使った日が7日分たまる間にそのサイトを一度も操作しないと、`localStorage` と IndexedDB を丸ごと消す（追跡防止。ホーム画面に追加したアプリは対象外）。旅行の相談のときだけ開く人では、消えるのが普通と考える（仮定：数週間〜数か月おきに開く）。
- 消えたら、何も覚えていないときと同じに参加の画面から入る（「前回の名前が見つかりませんでした」は出ない。消えたのか初めてなのかを見分けられないため）。一覧から自分の名前を選べば、元のメンバーに入れる（REQ-012）
- Android の Chrome と PC のブラウザでは、容量不足か利用者が消したときしか消えない
- iPhone の Chrome（中身は WebKit）でも同じに消えるかは、公式の記述がない。Phase 2 で実機で確かめる（要確認）

## 名前で参加する

```mermaid
sequenceDiagram
  actor U as 利用者
  participant App as 画面
  participant API as API（Worker）
  participant DB as D1

  U->>App: 招待URL /g/{groupId} を開く
  App->>API: グループを読む（groupId）
  API->>DB: グループ、メンバー、「行った」
  API-->>App: 見つからなければ「グループが見つかりません」（REQ-006）
  alt 端末が覚えているメンバーが今もいて、名前が合う（REQ-024）
    Note over App: 参加の画面を出さずにそのまま表示
  else 覚えていたが合わない（削除された）（REQ-025）
    App->>App: 覚えているメンバーを忘れる
    App->>U: 「前回の名前が見つかりませんでした」と、参加の画面
  else 覚えていない
    App->>U: 参加の画面（メンバーの名前の一覧と「新しく参加する」）
  end
  alt 一覧から自分の名前をタップ（REQ-012）
    Note over App: そのメンバーとして入る（API は呼ばない。D1 には書かない）
    App->>App: 端末に「このグループではこの番号・この名前」を覚える
  else 「新しく参加する」で名前を入れる（20人未満のときだけ出す）
    App->>API: 参加（groupId、名前、ボット対策のトークン）
    API->>DB: 1つの SQL で、グループがある・20人未満・名前が重複しない、を確かめて入れる
    alt 入れた
      API-->>App: メンバーの番号
      App->>App: 端末に覚える
    else 名前が使われている
      API-->>App: 「名前が使われている」と、その人の番号
      App->>U: 「（名前）さんはもういます」と「（名前）さんとして入る」
      Note over App: ボタンで入ったら端末に覚える。別の人なら名前を変えて送り直す
    else 満員・グループがない・通信エラーなど
      API-->>App: 断る理由
      Note over App: 何も覚えない（満員とグループがないはエラーの画面、ほかはその場でやり直す）
    end
  end
  App->>API: 部屋につなぐ（WebSocket。URL はグループIDの SHA-256、最初のメッセージでグループID）
```

- 名前の重複は D1 の `UNIQUE (group_id, name_key)` が守る（NFR-006 (11)）。2人がほぼ同時に同じ名前で入ったら、後の方は「名前が使われている」になるので、画面はグループを読み直して一覧を新しくする
- 名前をタップしたら、確かめずに入る（2026-11-09 にユーザーと決めた。それまでは名前を入れて「この人として続けますか？」と確かめていた）。押し間違えたら「メンバーを変更する」（REQ-056）で選び直す
- スマホを替えたときも、招待URLを開いて自分の名前を選べば、元のメンバーに入れる
- 「行った」の付け外しと退出は、API にグループIDとメンバーの番号を送る。API は、そのメンバーがそのグループにいることを、書き込む SQL の `WHERE` で確かめる（[data-model.md](data-model.md) の「メンバーの番号で操作する API の共通の決まり」）

## LINE のアプリ内ブラウザ

- 端末が覚えるものがブラウザごとに別なので、招待URLには `?openExternalBrowser=1` を付け、外部ブラウザで開かせる（NFR-002）
