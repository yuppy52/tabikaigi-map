## グループとメンバー

| 用語 | 意味 |
|---|---|
| グループ | 友達同士で地図を共有する単位。招待URLごとに1つ作られ、最大20人まで参加できる。メンバーが0人になると削除される |
| 招待URL | グループに参加するためのURL。知っている人は誰でも参加できる（参加する前に見えるのはグループ名とメンバーの名前だけ。REQ-002）。再発行はしない |
| メンバー | グループに参加している人。ログインなしなら名前だけの存在、ログインありならアカウントと紐づく |
| 作成者 | グループを作った人（作成者のメンバー）。作成者のメンバーで決まり、名前やアカウントの `uid` では決まらない（ログインありの作成者は名前を変えられる）。グループの管理できる人の初期設定（「誰でも」）を持ち、「作成者のみ」に変えられる（変えられるのは、作成者のメンバーがアカウントに紐づいていて、その人がログインしているときだけ。REQ-045）。作成者のメンバーが消える（退出・削除・退会）と、そのグループの作成者はいなくなる |
| 管理できる人 | メンバーの削除、グループ名の変更、グループの削除ができる人の範囲。「誰でも」（初期値）か「作成者のみ」を、ログインしている作成者が選ぶ（REQ-045）。退出（自分のメンバーを消す）と、自分の名前の変更は、この設定に関係しない |
| 名前 | メンバーの名前。グループごとに入力する（ログインありも同じ。アカウントは表示名を持たない）。1グループの中で、ログインあり・なしを問わず重複しない。変えられるのはログインありの本人だけ。紐づいたメンバーの名前では、ほかの人は参加できない |
| 退出 | メンバーが自分でグループから抜けること。グループでの「行った」は消える（アカウントの「行った」は残る）。最後の1人が退出すると、グループも削除される。作成者が退出すると作成者はいなくなり、管理できる人は「誰でも」になる |
| 枠 | 1グループに20ある、メンバーの入れ物（設計上は `s0`〜`s19`）。メンバーが抜けると空き、次に参加した人が使う |
| 信頼ベース | 本人確認をせず、名前を入力すれば誰でもその人として操作できる仕組み。ログインなしの前提になっている考え方 |

## 地図と「行った」

| 用語 | 意味 |
|---|---|
| 行った | メンバーやアカウントが訪れたことのある都道府県。地図の色や一覧の状態で表す |
| わたし | 地図の表示モードの1つ。自分の「行った」を付け外しする |
| みんな | 地図の表示モードの1つ。行った人が多い県ほど濃く塗り、全員まだ行っていない県を強調する |
| 全員まだ行っていない県 | グループのメンバーの誰も「行った」にしていない県。次の旅行先の候補として、「みんな」で強調し、数と県名の一覧を出す（REQ-018・REQ-054） |
| メンバー別 | 地図の表示モードの1つ。選んだメンバー1人の「行った」だけを表示する |

## アカウントとログイン

| 用語 | 意味 |
|---|---|
| ログインなし | 会員登録せず、名前を入れるだけで参加する使い方。裏では匿名で認証しているが、利用者には見せない。「行った」はグループのメンバーごとに持つ |
| ログインあり | メール＋パスワードまたはGoogleでログインする使い方。「行った」はアカウントに保存し、参加している全グループに同期する |
| 匿名（匿名認証） | ログインなしで使うときに、裏側で自動的に行われる認証（Firebase を使う場合の仕組み。「認証済み」も同じ。バックエンドは Q-023 で見直し中）。利用者に見せる概念ではない。これだけでは「アカウント」とは呼ばない |
| 認証済み | 匿名を含め、何らかの形でサインインしている状態。Firestoreのセキュリティルールで「書き込んでよいか」の条件に使う |
| ログイン済み | メールまたはGoogleでサインインしている状態（匿名を含まない）。メールアドレスの確認が済んでいない人は含まない（ログインなしとして扱う。REQ-057）。例：「管理できる人」を「作成者のみ」に変えられるのは、ログイン済みの作成者だけ |
| アカウント | メールアドレスやGoogleと結びついた、ログインする人の記録（設計上の名前：`users/{uid}`。バックエンドが決まったら直す：ADR 0003）。匿名の認証だけの状態は含まない。表示名は持たない。確認待ちのアカウントも「すでに使われているメールアドレス」（REQ-058）に含む |
| 確認待ち | メールアドレス＋パスワードでアカウントを作ったが、確認メールのリンクをまだ開いていない状態。アカウントはあるが、ログインなしとして扱う（メンバーに紐づけない、作成者として設定を変えられない。REQ-057・NFR-006 (10)） |
| 昇格 | ログインなしで参加していた人が、**まだどのアカウントにも使われていない**メールやGoogleでアカウントを作ったとき、匿名のときと同じ `uid` のままアカウントにすること。すでに別のアカウントで使われているメールやGoogleでログインする場合は昇格にならず、既存のアカウントへの紐づけ（UC-09）の流れになる（このとき `uid` は変わる）。どちらの場合も、作成者のメンバーを紐づければ作成者の立場を引き継ぐ。同じ端末からログインなしで参加している他のグループのメンバーは、ログインしたときには紐づけず、あとでそのグループを開いたときに紐づける（requirements の REQ-040） |
| G・U | 紐づけるときに比べる2つの「行った」。G はそのグループのメンバーとしての「行った」、U はアカウントの「行った」（REQ-038） |
| 合算 | 紐づけるとき、G と U の両方に県があって食い違うときに選べる扱いの1つ。G と U を合わせたもの（どちらかで行った県をすべて）をアカウントに保存する。もう1つの扱いは「アカウントのデータを使う」（G を捨てる）。ユースケース UC-09「『行った』を合算する」は、この選択を含む引き継ぎの流れ全体を指す（REQ-038） |
| 紐づけ | 名前だけで参加していたメンバーに、ログインしたアカウントを結びつけること。以後、そのメンバーの「行った」と名前は本人しか変えられない（REQ-031。メンバーの削除は「管理できる人」の設定に従う） |
| 紐づいたメンバー | アカウントに紐づけ済みのメンバー。「ログインしたメンバー」とは呼ばない（ログアウトしても紐づいたままのため） |
| 本人確認 | ログインした人がグループに入るとき、入れた名前と同じ名前の（アカウントと紐づいていない）メンバーが自分かどうかを確認するダイアログ。自己申告で、本当に本人かは確かめていない |
| ログアウト | ログインありの状態をやめること。トップの画面に戻り、以後はログインなしとして扱う |
| 退会 | ログインありの人が、アカウントを削除すること。参加していた各グループのその人のメンバーも消える（退出と同じ扱い） |

## 画面

| 用語 | 意味 |
|---|---|
| トップ | アプリの入口の画面。ログアウトした後もここを開く。中身は基本設計で決める（要確認：Q-016） |
| グループ設定 | グループ名、管理できる人、メンバーの削除、グループの削除、退出、自分の名前の変更（ログインありのみ）を行う画面 |
| マイページ | ログインしたときだけ入れる、アカウントの「行った」とメールアドレスを見て、ログアウト・退会する画面 |
| グループ一覧 | ログインしたときだけ入れる、参加中のグループを切り替える画面 |
