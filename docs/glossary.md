## グループとメンバー

| 用語 | 意味 |
|---|---|
| グループ | 友達同士で地図を共有する単位。招待URLごとに1つ作られ、最大20人まで参加できる。メンバーが0人になると削除される |
| 来訪者 | まだグループに入っていない人。招待URLを開いた人（[use-cases](use-cases.md) のアクター、[権限マトリクス](design/permissions.md) の列） |
| 招待URL | グループに参加するためのURL。知っている人は誰でも参加できる（参加する前に見えるのはグループ名とメンバーの名前だけ。REQ-002）。再発行はしない |
| メンバー | グループに参加している人。名前だけの存在で、会員登録はしない |
| 名前 | メンバーの名前。グループごとに入力する。参加の画面では、すでにいる人は名前を選んで入る（REQ-012）。1グループの中で重複しない。誰も変えられない（REQ-015）。使えない文字は REQ-009 |
| 退出 | メンバーが自分でグループから抜けること。そのメンバーの「行った」は消える。最後の1人が退出すると、グループも削除される |
| 枠 | **使わない言葉**（2026-10-10：案 C では、メンバーを使い回さない番号で持ち、20人の上限は人数で数える。[data-model](design/data-model.md)）。案 A で、1グループに20あるメンバーの入れ物（`s0`〜`s19`）だった |
| 信頼ベース | 本人確認をせず、名前を選べば誰でもその人として操作できる仕組み。このアプリ全体の前提になっている考え方 |

## 地図と「行った」

| 用語 | 意味 |
|---|---|
| 行った | メンバーが訪れたことのある都道府県。地図の色や一覧の状態で表す |
| わたし | 地図の表示モードの1つ。自分の「行った」を付け外しする |
| みんな | 地図の表示モードの1つ。行った人が多い県ほど濃く塗り、全員まだ行っていない県を強調する |
| 全員まだ行っていない県 | グループのメンバーの誰も「行った」にしていない県。次の旅行先の候補として、「みんな」で強調し、数と県名の一覧を出す（REQ-018・REQ-054） |
| メンバー別 | 地図の表示モードの1つ。選んだメンバー1人の「行った」だけを表示する |

## 使わなくなった言葉（ログイン）

2026-11-06 にログインをやめた（[ADR 0013](adr/0013-drop-login.md)）ので、次の言葉は**使わない言葉**にした：ログインなし、ログインあり、ログイン済み、アカウント、確認待ち、G・U、合算、紐づけ、紐づいたメンバー、本人確認、ログアウト、退会、作成者、管理できる人、ログインの状態の目印、確認待ちの表示、アカウントの入口、マイページ、グループ一覧。それより前の「匿名（匿名認証）」「認証済み」「昇格」「枠」も使わない。意味は git の履歴に残る。

## 画面

| 用語 | 意味 |
|---|---|
| トップ | アプリの入口のページ（`/`。検索に出す素の HTML。[screens](design/screens.md) の「トップと URL」） |
| メニュー | グループの画面のヘッダーから開く一覧。グループ設定、トップ、プライバシーポリシー、問い合わせ |
| 確認ダイアログ | 退出・削除など、取り消せない操作の前に出す確認 |
| リアルタイムの知らせ | 部屋（Durable Objects）から、同じグループの画面を開いている人に配るもの（「行った」の付け外し、「取り直して」。[architecture](design/architecture.md)） |
| エラー | グループが見つからない、通信エラー、いまは使えない、を出す画面（満員は参加の画面の一言で伝える：2026-11-10） |
| グループ設定 | グループ名の変更、メンバーの削除、グループの削除、退出、メンバーを変更する、を行う画面（[screens](design/screens.md)） |
| メンバーを変更する | 端末が覚えているメンバーを忘れて、参加の画面に戻る操作。メンバーは消さない（REQ-056） |

## その他

| 用語 | 意味 |
|---|---|
| 端末 | 利用者が使っているスマホやPC（実際にはブラウザごと）。前回この端末で使ったメンバーを、グループごとに覚えておくのに使う（[auth-flow](design/auth-flow.md) の「端末が覚えるもの」） |
| 運営者 | このアプリを作って動かす人（1人）。利用状況、無料枠の使用量、エラーを見る（requirements の NFR-010〜NFR-014）。グループのメンバーとは別の立場 |
| サービスのコンソール | 使うサービスが用意する管理用の Web の画面（Cloudflare のダッシュボード、Sentry）。使用量やエラーを見る。「運営者用の管理画面」とは別 |
| 運営者用の管理画面 | 運営者が利用状況と使用量を1画面で見るために、自分で作る画面。運営者の PC で動かす。MVP の次に作る（Q-030） |
| 無料枠 | 使っているサービスを無料で使える量の上限（保存できる量、1日の読み書きの回数など）。超えたら請求されるのではなく止まる構成にする（NFR-004） |
