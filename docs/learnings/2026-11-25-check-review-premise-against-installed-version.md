# 部品の動きを前提にした指摘は、入っている版で確かめてから直す

## 何が起きたか
S-6（公開の前の `access-reviewer`）の #6 で、「本文を読むところの `catch` が `bodyLimit` の失敗まで飲み込み、413 が 400 になる」という指摘が出た。直す前にテスト（Content-Length を付けずに少しずつ送る本文）を書いて確かめたところ、入っている Hono 4.13.18 の `bodyLimit` は、自分で本文を読んで `onError`（413）を返すだけで、例外を投げなかった。指摘の前提は、この版では成り立っていなかった。

## 原因
レビューをする側は、部品の一般的な動き（または前の版の動き）から推測して書く。入っている版のコードやテストまでは見ていない。

## どうしたか
- 413 になることを確かめるテストを残した（S-6b の 8-E。版を上げて動きが変わったときに気づける）
- `catch` は `SyntaxError` だけを受けて、ほかは投げ直す形にした（前提が違っても、守りとしては害がない）

## 次にどうするか
- 部品（npm）の動きを前提にした指摘は、直す前に、入っている版（`package-lock.json` の版、`node_modules` のコード、または小さなテスト）で確かめる
- 確かめた結果は、前提が当たっていても外れていても、テストとして残す
- 外れていたら、レビューの返事に「この版では起きない（確かめたテスト）」と書く
