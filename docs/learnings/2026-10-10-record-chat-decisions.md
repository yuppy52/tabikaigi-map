# 会話で決めたことは、その場で文書に書く。数字を出すときは出どころを添える

## 何が起きたか
`/review-docs` の反映で、メンバーの色を「モックと同じ6色」と提案したところ、ユーザーから「10色にするってなってなかった？正直20色用意したいが、途中で6色の方がいいとなった？」と聞かれた。
requirements・use-cases・open-questions（Q-008）・git の履歴を探したが、色の数を決めた記録はどこにもなかった。文書にあったのは「使われていない色から順に。足りなければ重複してよい」（REQ-021）だけで、6色はモック（`tools/template.html`）の値だった。改めて聞いて10色に決めた。

## 原因
- 以前の会話で色の数に触れたとしても、決めたこととして文書に書かれていなかった（会話は次のセッションに残らない）
- 提案のときに「6色」がどこから来た数字か（モックの値で、決めたことではない）を書かなかったので、ユーザーは「決まっていたことが変わった」と受け取った

## どうしたか
ユーザーに「記録が見つからない。6色はモックの値だった」と説明し、選択肢（20・10・6）を並べ直して10色に決めた。REQ-021 と data-model に、決めた日付と一緒に書いた。

## 次にどうするか
- ユーザーと会話で何かを決めたら（数字、方針、やらないこと）、同じセッションの中で requirements か open-questions に「決めた日付」付きで書く。「あとでまとめて書く」にしない
- 数字や方針を提案するときは、出どころを添える：「決定済み（REQ-xxx）」「モックの値」「仮に置いた値」「推奨（理由）」
- ユーザーが「〜って決めてなかった？」と言ったら、まず文書と git の履歴を探し、見つからなければ「記録がない」と正直に伝えてから聞き直す

## 追記（2026-10-12、推奨と違う案を選んだときの理由）
Q-017 で、ユーザーは推奨（紐づいたメンバーの記憶だけ忘れる）ではなく「ログアウト・退会でも何も忘れない」を選んだ。記録には理由を「REQ-040 を保つため」と書いたが、REQ-040 は推奨案でも保たれていた。`/review-docs`（2026-10-12）の #11 で、理由の取り違えを指摘された。選んだ案で実際に変わったのは「紐づいたメンバーの記憶が残り、次に開いたときに REQ-035 の案内が出る」ことだった。
- 次にどうするか：ユーザーが推奨と違う案を選んだら、記録には「推奨は何だったか」と「選んだ案で、推奨と比べて何が変わるか」を書く。両方の案に共通する利点を、選んだ理由として書かない（`.claude/rules/docs.md` の「決めたことの反映」に足した。2026-10-12、ユーザーの OK）
