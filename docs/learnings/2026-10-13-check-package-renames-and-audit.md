# 部品を入れたら、非推奨の警告と npm audit を見て、改名や直った版を確かめる

## 何が起きたか
2026-10-12 に開発環境を作るとき、試作（`spike/`）と同じ `@cloudflare/vitest-pool-workers` を入れた。テストは通ったが、実行のたびに「`@cloudflare/vitest-plugin` に名前が変わった。この名前には今後更新が来ない」という警告が出ていた。`npm audit` では high が4件あり、古い名前の部品が、直っていない古い `miniflare`・`sharp`・`undici` を抱えていた。

## 原因
- 試作の版をそのまま写した。試作から2か月の間に、部品の名前が変わっていた
- インストールの最後の行（「found 0 vulnerabilities」）だけを見て、別の時点の `npm audit` の結果と取り違えかけた

## どうしたか
- `@cloudflare/vitest-plugin` に入れ替え、high が残る版（1.3.7）から直った版（1.4.0）に上げて、`npm audit` が0件になったことを確かめた
- `wrangler` も直った版（4.149）に上げた
- `npm ci` でロックファイルだけから入れ直して、テストが通ることを確かめた（GitHub Actions と同じ手順）

## 次にどうするか
- 部品を入れたり上げたりしたら、テストの出力の警告（非推奨、改名）と `npm audit` を見る。high 以上が残るなら、直った版があるかを確かめてから進む
- 試作の設定や版を写すときは、そのまま使わず、今の版と名前を確かめる
- 新しく作ったサブエージェントは、作ったセッションでは呼べない（次のセッションから）。同じセッションで使うときは、汎用のエージェントにその定義ファイルを読ませて代わりにする

2026-10-13：ユーザーの OK をもらい、CLAUDE.md の「技術の前提」に反映した。

## 追記（2026-10-16）：大きな道具を足す前に、いまの部品とデータでできないかを見る
- 地図データを国土数値情報に替えるとき、市区町村を都道府県にまとめる定番の道具 mapshaper を入れた。部品が229個増え、非推奨の警告が2つ出た（1つは「バッファの読み過ぎの恐れがあるので乗り換えて」）。`npm audit` は0件だった
- いまの地図のスクリプトがすでに使っている topojson の部品で足りると気づき、外した。足したのは同じ作者の小さな部品1つ（2個増）。さらに、元のデータの zip に都道府県単位にまとめたものが入っていて、まとめる処理そのものが要らなかった
- 次は：道具を足す前に、(1) 元のデータに、欲しい形のものが入っていないか（zip の中身を一覧する）、(2) いま入っている部品でできないか、を先に見る。足すなら、増える部品の数と警告を見て比べる

2026-10-16：追記の分を、ユーザーの OK をもらい、CLAUDE.md の「技術の前提」に反映した。

## 追記（2026-10-22）：手で入れる版も7日待つ。npm が自身の不具合で止まったら、新しい npm を1回だけ使い、npm 10 の `npm ci` で確かめる
- 2026-10-19 に React を入れるとき、最新の 19.3.1 は公開から5日だった。Dependabot と同じく、出てから7日たった 19.3.0 を選んだ。19.3.1 の中身（このアプリが使わない Server Components の修正）を GitHub のリリースで確かめてから決めた。7日の後に Dependabot が上げる
- 同じ日に `vite` を足すと、npm 10.9.7（Node 22 に付いてくるもの）が `Cannot read properties of null (reading 'edgesOut')` で止まった。npm 10.9.9 でも同じだった。部品の組み合わせ（vitest の任意の相手の部品）を読むところの、npm 自身の不具合だった。npm 11.21.0（公開から7日以上たっていた）を `npx npm@11.21.0 install` で1回だけ使って入れた。できた `package-lock.json` は npm 10 の `npm ci` で入れ直せ、テストも通ることを確かめた（CI は npm 10 のまま）
- 次は：手で入れるときも、公開から7日たった版を選ぶ。新しい版を選ぶなら、理由（安全の修正など）を確かめて書く。npm が止まったら、`package.json` を手で直したり `--legacy-peer-deps` を使ったりせずに、新しい npm（7日たった版）で1回だけ入れる。そのあと、CI と同じ npm の `npm ci` とテストで確かめる。使ったことは ADR か作業の記録に書く（ADR 0010 に書いた）

2026-10-22：追記の分を、ユーザーの OK をもらい、CLAUDE.md の「技術の前提」に反映した。
