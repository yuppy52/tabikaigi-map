# 名前の決まりに見えない文字の扱いがないと、見た目が同じ別の名前でなりすませる

## 何が起きたか
REQ-009〜REQ-011（名前の決まり）は「前後の空白を取る」「見た目の文字数」「全角半角・大文字小文字を同じとみなす」を決めていた。API を作った後の `access-reviewer` で、「ゆう」の後ろに幅のない空白（U+200B）を足した名前が、比べる形（`name_key`）が別になるので `UNIQUE` を通り抜け、紐づいた「ゆう」と見た目が同じ別のメンバーとして入れると分かった。ハングルの空白に見える文字（U+3164）だけの名前など、見た目が空の名前も入れた。

## 原因
- 「同じ名前」を NFKC と小文字でそろえることだけを考え、そろえても消えない見えない文字（書式の制御文字、向きを変える文字、空白に見える文字）を考えていなかった
- 前後の空白を `\s` で取れば空白だけの名前は防げると思っていたが、`\s` に入らない空白に見える文字がある

## どうしたか
- 見えない文字（制御文字、書式の文字、私用の文字、行・段落の区切り、空白に見える文字）を含む名前は 400 にした。ただし絵文字に要る ZWJ（👨‍👩‍👧）と、旗の絵文字のタグ文字は通す
- REQ-009・REQ-010 に一文足した。断る文字と、通す絵文字をテストに並べた

## 次にどうするか
- 人が入れる文字列（名前、グループ名、問い合わせ）の決まりを作るときは、見えない文字・向きを変える文字・空白に見える文字をどうするかも決める
- 断る文字を足すときは、絵文字（ZWJ、異体字の切り替え、タグ文字）を壊さないことをテストで確かめる。新しい絵文字が断られないよう、まだ割り当てのない文字は断らない

## 追記（2026-10-13）：断る文字の一覧に、結合文字と記号の仲間が抜けていた

名前の変更の API を作った後の `access-reviewer` で、断る文字の一覧の漏れが見つかった。漏れていたのは、Unicode の分類が「書式（Cf）」や「制御（Cc）」ではないのに見えない文字。
- 異体字の切り替え（U+FE00〜U+FE0F、U+E0100〜U+E01EF）、組み合わせを表す記号（U+034F）、モンゴル文字の切り替え（U+180B〜U+180D）：どれも結合文字（Mn）で、NFKC でも消えない
- 点字の空白（U+2800）：記号（So）で、見た目は空

「ゆう」＋U+FE00 で、見た目が同じ「ゆう」がもう1人作れた。分類（`\p{Cf}` など）で断る作りだったので、分類の外にある見えない文字が抜けた。

どうしたか：上の文字を断る一覧に足した。U+FE0E・U+FE0F（絵文字の形の切り替え）は、絵文字の直後だけ通す（❤️、1️⃣ を壊さない）。テストに断る文字と通す絵文字を足した。

次にどうするか：見えない文字は、分類（Cf・Cc など）だけでなく、結合文字（Mn）と記号（So）の中の見えないものも確かめる。断る一覧を足したら、絵文字の直後の U+FE0F を壊していないかもテストする。

## 追記・2回目（2026-10-15）：自分で並べた一覧は、また漏れた。例外は、それが要る場所でだけ効かせる

`/review-docs` と、その直しの `access-reviewer` で、名前の守りの穴がさらに見つかった。
- 「絵文字に要るから通す」としていた ZWJ・旗のタグ文字・U+FE0F が、絵文字の外でも通っていた（「ゆ＋ZWJ＋う」）
- 🏴 の後ろなら、決まりのないタグ文字の並びも通っていた（黒い旗だけが見え、タグ文字は見えない）
- Unicode が「表示しない」と決めている文字のうち、分類（Cf など）の外にあるもの（クメール文字の U+17B4、割り当てのない場所）が漏れていた
- 絵文字を ZWJ や肌の色の記号で何十もつなぐと、見た目の1文字と数えられ、10文字の上限を超えられた

原因：断る文字を、分類と自分で見つけた文字で並べていた（2回とも、並べ忘れが穴になった）。例外（絵文字の部品）を文字の単位で通していて、どこにあるかを見ていなかった。

どうしたか：
- 断る文字は、Unicode の決めた一覧（`\p{Default_Ignorable_Code_Point}`）を使い、自分で並べるのは点字の空白などの残りだけにした
- 絵文字の部品は、決まった並び（絵文字と絵文字の間の ZWJ、絵文字の直後の U+FE0F、キーキャップ、決まりのある3つの旗）のときだけ取り除いてから調べる
- 見た目の1文字に使える部品を10までにした
- 比べる形（`name_key`）で、見た目を変えない部品を取り除き、続いた空白をまとめた。見た目が同じなら同じ名前とみなす（同じとみなしすぎても、断る側に倒れるだけ）

次にどうするか：
- 文字の決まりは、自分で一覧を作る前に、Unicode が決めている性質（Default_Ignorable、Extended_Pictographic など）があるかを探す
- 守りに例外を作るときは、「どこでなら通すか」（前後の並び）まで決めて、その外では断る。例外の境目（頭・終わり・2つ続く・違う相手の後ろ）をテストに並べる
- 「見た目が同じ」を守りたいときは、断る文字を増やすより、比べる形のほうで見た目を変えない部品を取り除く（なりすましの道が、一覧の漏れに左右されなくなる）
