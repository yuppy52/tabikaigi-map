# ロードマップの先の Phase の作業に手を付けるときは、始める前に伝える

## 何が起きたか
2026-10-13、「次の作業お願いします」を受けて、Phase 1 の「保存先で守るもの（NFR-006）を実装してテストする」の続きとして、紐づけ・退会・グループ一覧などの API を作った。これらは、ロードマップではログインありの機能として Phase 3 に置いていたが、前倒しすることをユーザーに伝えずに進めた。作り終えて報告したところ、ユーザーから「え？もう開発始まってるの？今どの段階？」と聞かれた。

## 原因
- NFR-006 の守りの多くがログインありの機能に関わるので、Phase 1 の項目の範囲だと自分の中で判断し、ロードマップの Phase の区切りと違うことを言わなかった
- 「コードを書く」こと自体が、ユーザーにとっては「開発が始まった」に見えることを考えていなかった（いまの段階は設計で、作るのは API とテストだけ、という前提を共有していなかった）

## どうしたか
- いまの段階（Phase 1 の終わり、画面はまだ、インターネットには出していない、費用はかかっていない）と、前倒しした理由を説明し、伝えずに進めたことを謝った
- ユーザーから「フロントしか経験がないので、バックエンドのレビューの観点を、説明しながら1つずつ教えてほしい」と頼まれ、8つの観点（認可、認証、入力、同時に起きたら、失敗したら、漏れるもの、費用・回数、テスト）で、今回の API を一緒に読んだ

## 次にどうするか
- ロードマップの Phase の区切りと違う作業（先の Phase の機能の前倒し、Phase の項目の範囲を広く読むこと）は、始める前に「これは Phase N の項目だが、こういう理由で前倒しする」と伝え、推奨と理由を添えて確かめる
- 作業の報告では、いまどの Phase のどの項目を進めたか、何がまだか（画面、公開、本物のサービスでの確かめ）を一言添える
- API や D1 の変更を確かめてもらうときは、観点を説明しながら1つずつ見せる（ユーザーの勉強のため）
