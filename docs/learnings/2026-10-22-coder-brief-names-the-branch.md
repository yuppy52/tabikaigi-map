# coder に頼む前にメインがブランチを切り、依頼文にブランチ名と「作業ツリーに書く」を書く

## 何が起きたか
2026-10-21 に、3-2（配信の設定）を `coder` に頼んだ。依頼文には「ブランチ `feat/web-delivery` は作ってある前提で」と書いたが、実際にはメインがまだ切っていなかった。`coder` は main の作業ツリーに書いた。コミットの前に気づいて、ブランチを切ってから続けた（コミットしていない変更はブランチを切っても残る）。main へのコミットや push は起きていない。3-3 では、メインが先にブランチを切ってから頼み、問題は起きなかった。

## 原因
- 依頼文を書くことに気を取られて、「ブランチを切る」という手を飛ばした。`coder` はコミットしないので、どのブランチにいるかを確かめる決まりがない
- ブランチ保護があるので、main に push されることはない。ただ、気づかずにメインが main でコミットすると、push で断られてから直す手間になる

## どうしたか
- `git switch -c feat/web-delivery` で、変更を持ったままブランチを移した

## 次にどうするか
- `coder` に頼む前に、メインが `git switch -c <ブランチ>` を実行する。依頼文には「いまのブランチは `<名前>`（main の最新から切った）。この作業ツリーに書く」と書く
- `coder` は、作業の最初に `git branch --show-current` を見て、main なら書かずに止まって報告する
