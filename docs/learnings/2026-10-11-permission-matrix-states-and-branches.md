# 権限の表は、立場を状態の組み合わせで並べ、× を「保存先で断る」と「画面だけ」に分ける。起きない分岐は作らない

## 何が起きたか
requirements と data-model をもとに権限マトリクス（[permissions.md](../design/permissions.md)）を下書きした。`/review-docs`（2026-10-11、14件）で、重大2件と、表にして初めて見えた問題を指摘された。
- **立場が足りなかった**（#1）：「ログイン済みで、このグループにはまだ自分に紐づいたメンバーがいない人」の列がなかった。その人の動き（紐づけられる）を「紐づいたメンバーの本人」の列に書いていたため、本当の本人の欄が誤っていた（2人目は `UNIQUE (group_id, uid)` で断られる）
- **× の意味が2種類混ざっていた**（#2）：API が断る × と、画面だけで止めていて API は通す ×（参加前の地図など）が同じ記号だった。「× の欄ごとにテストする」と書いていたので、そのままでは必ず失敗するテストを書くことになる
- **起きない分岐があった**（#3）：data-model に「作成者のみ」のとき「紐づいていない作成者の番号を送れば通す」があった。しかし「作成者のみ」にできるのは紐づいた作成者だけで、紐づけを外す操作はない。この分岐を通る場面はなく、運営者が手で `uid` を空にしたときなどに抜け道になる
- 証明書（ID トークン）を確かめられないときにログインなしに落とすと、ログイン中の人に紐づいていないメンバーが黙って作られる（#8）

## 原因
- 立場を「ログインなし／紐づいた本人／作成者」と、思いつく人の種類で並べた。「ログインしているか」と「そのグループで紐づいているか」の組み合わせで数えなかったので、間の状態が抜けた
- 「できない」の守り方は、API・制約・画面の3通りあるのに、記号を1つにした
- 分岐の条件を、「そもそもその状態に入れるか」（状態がどう移り変わるか）で確かめなかった
- 失敗したときの扱いを、「わからなければ弱い権限で続ける」と無意識に置いていた

## どうしたか
- 立場に「ログイン済み（まだ紐づいていない）」を足した。記号を ×（API・制約で断る。テストする）と ×画（画面だけ）に分け、〔未〕（D1 で未確認の守り方）の印も付けた
- ユーザーと決めて、「作成者のみ」は紐づいた本人だけが通る形にし、起きない分岐を消した
- トークンが確かめられないときは 401/503 で止め、ログインなしとして扱うのは「署名は正しく `email_verified` が false」のときだけにした

## 次にどうするか
- 権限の表の立場は、状態の組み合わせ（ログインしているか × そのグループで紐づいているか × 作成者か、確認待ちか）で数え、組み合わせごとに列か注記があるかを確かめる
- 「できない」は、どこで止めるか（API／制約／画面）で記号を分ける。画面だけのものはテストの対象から外し、「分かっている限界」に書く
- 条件の分岐を書いたら、その条件に入る操作の順番が実際にあるかを確かめる。ない分岐は作らず、「なぜ起きないか」を一文残す
- 認証や確認に失敗したときは、弱い権限に落として続けず、止めてエラーにする（落としてよいのは、確かめた結果として弱い権限だと分かったときだけ）

## 再発（2026-10-11、画面の遷移図）
Q-020 で screens の遷移図を書き直したとき、同じ形の指摘を `/review-docs`（21件）で受けた。
- 「端末が覚えているメンバーと名前が合う → グループ」に「紐づいていなければ」が抜け、ログイン済みの人が紐づけ（合算、REQ-039、上限）に入る分岐もなかった（#2・#10）。立場を「ログインしているか × 紐づいているか」で分けずに、思いつく流れで矢印を引いた
- **行き止まり**があった（#3）：グループが0個のログイン済みの人と、トップで登録した確認待ちの人が、マイページにもログアウトにも着けなかった。入口を「グループの画面のメニュー」だけに置き、そこへ来られない状態を数えなかった
- 紐づけに失敗した後（10グループの上限、別のアカウントに紐づき済み）の画面がなかった（#4）

次にどうするか（画面）：
- 遷移図の分岐は、権限の表と同じ立場の組み合わせ（ログインなし／確認待ち／ログイン済み × 紐づいているか × 作成者か）で分ける
- 立場ごとに、ログアウト・退会・トップへの出口があるかを確かめる（特に「グループが0個」「確認待ち」「失敗した直後」）
- 失敗の矢印（断られた、上限、見つからない）の先と、そのとき端末が覚えているものを書く

## 仕組みへの反映
`.claude/agents/doc-reviewer.md` の「権限」に3項目（立場の組み合わせと × の分け方、起きない分岐と「戻す手はない」、失敗したときに弱い権限に落とさない）を足した。失敗したときの決まりは、Phase 2 で API のルールを作るときに入れる（roadmap に書いた）（2026-10-11、ユーザーの OK）。
